# 架构

```text
用户规范 + 选择目录
       ↓
本地扫描 → 请求字段预览 → Chat Completions（OpenAI / DeepSeek / 小米 MiMo）
       ↓                              ↓
       └────────── 本地计划校验 ← JSON 建议
                       ↓
                 用户逐项审核
                       ↓
                本地移动与交易记录
                       ↓
                    核验 / 撤销
```

`Policy` 保存用户原文、版本和 SHA-256 哈希。每次保存新版本后，界面丢弃旧扫描和旧计划。`Scanner` 只读元数据，给扫描项分配本次有效的文件 ID。`ModelClient` 构造兼容 Chat Completions 的请求；测试连接只发送固定短句。三个服务商使用相同响应解析，但认证头分别按预设设置。

`PlanValidator` 要求固定 JSON 字段、最多 50 项移动、存在的规则和文件 ID、相同规范哈希和扫描 ID，以及授权目录内的目标相对文件夹。程序在本机追加原文件名，不允许模型改名。文件内容、模型输出中的其他动作和命令从未交给执行器。

`Executor` 再核对文件类型、大小、修改时间和文件编号，拒绝同名覆盖，先写入操作意图再移动，随后核验实际位置。历史保留每项状态。应用启动时会重新核验未定状态；撤销同样检查冲突和文件状态。

此版本尚未实现对自然语言规则语义的机械证明。因此所有建议都必须由用户逐项审核。参见 [后续方向](ROADMAP.md)。
