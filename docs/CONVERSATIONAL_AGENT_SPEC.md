# 对话式规则管家：产品与工具协议

## 目标与首屏

首屏是对话工作台。新用户只需配置 OpenAI、DeepSeek 或小米 MiMo 的 API 密钥，选择一个目录，然后用自然语言描述自己的整理习惯。助手负责把习惯写成有编号的用户规则、扫描、解释文件情况、提出移动计划和报告执行结果。界面始终显示当前模型、规范版本、授权范围和待确认计划。规范、历史及连接设置可从侧边栏打开，但不是完成任务的必经页面。

空状态提供可点击示例问题，不内置任何可执行管理规则。首次连接提供服务商预设模型与接口地址；用户可以改写。对话区明确说明：聊天文字、用户规则和工具返回的数据会发送到选定的模型接口；文件名与相对路径需要用户单独允许，文件内容和 API 密钥不会发送。

## 工具协议 v1

应用通过 OpenAI 兼容的 Chat Completions `tools` / `tool_calls` / `tool_call_id` 循环调用模型。工具由本地应用实现，模型没有任意命令执行或文件读写能力。每条用户消息最多进行 8 次模型请求、12 次工具调用；超过上限则提示用户缩小任务。未知工具、参数、越界路径及过期状态均由本地拒绝。服务商可切换，模型标识和 HTTPS 地址可编辑。

| 工具 | 功能 | 条件 |
| --- | --- | --- |
| `workspace_status` | 查看连接、目录、规范和扫描摘要 | 只返回必要状态 |
| `read_rules` | 读取用户保存的规范正文 | 正文会发往模型服务商 |
| `choose_folder` | 弹出 macOS 目录选择器 | 必须由用户在系统面板选择 |
| `scan_files` | 扫描授权目录内的普通文件 | 本地只读，不读取文件内容 |
| `list_files` | 分页返回文件 ID、元数据，可选相对路径 | 用户需在界面开启“共享文件元数据”；每页最多 100 项 |
| `save_rules` | 将用户表述整理为带 `R001:` 编号的规则并保存新版本 | 本地校验；保存后旧扫描/计划失效 |
| `prepare_moves` | 提交结构化移动建议 | 本地验证规则、扫描 ID、路径和证据；仅生成预览 |
| `list_history` | 查看最近移动结果 | 始终返回状态；仅在允许共享文件名时返回相对路径 |
| `undo_move` | 撤销指定已核验移动 | 用户本轮明确要求撤销，且本地核验无冲突 |
| `execute_approved_plan` | 执行待确认计划 | 用户在当前计划上明确输入“确认执行”或点击确认按钮后才可调用 |

模型计划只支持授权目录内的普通文件移动，最多 50 项。每项必须引用现存规则和扫描文件 ID，写明目标相对文件夹、原因及证据。程序追加原文件名；不得改名、覆盖、删除或执行脚本。计划预览在本地显示完整路径；返回模型的工具结果只有在用户允许共享文件名时才包含来源与目标路径。执行前逐项再次检查文件状态，并记录可核验的历史。重新扫描、更换目录或保存规则使待确认计划失效。

## 对话状态与异常

本轮对话保留在应用进程内，重启后不恢复。模型应优先使用工具获取状态，缺少目录或规则时引导用户完成，不猜测已扫描文件。接口不可用、模型不支持工具、费用或额度错误时，在对话中显示可操作的错误；不会降级成未经校验的自然语言文件操作。扫描不完整时禁止准备移动计划。文件名、规则文本及模型输出均按不可信数据处理。

## 验收场景

1. 全新用户看到连接卡、目录按钮和示例话术；无需理解规则编号即可说出偏好，助手用 `save_rules` 写入并反馈版本。
2. 用户说“按我的规则整理这个目录”，助手调用扫描、分页清单并生成预览；共享开关关闭时只说明需要用户允许，不泄露文件名。
3. 计划以来源、目标、规则、原因和证据展示；没有确认时模型调用执行工具被拒绝。
4. 用户在对话输入“确认执行”，应用执行当前计划并把成功/失败数显示在对话和历史里；旧计划不能重复执行。
5. 用户说“撤销刚才的移动”，助手通过历史找到 ID 后撤销；冲突时解释原因。
